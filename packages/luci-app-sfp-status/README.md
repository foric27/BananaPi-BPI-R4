# luci-app-sfp-status

Приложение LuCI для OpenWrt 24.10, предназначенное для чтения телеметрии DOM одного или нескольких модулей SFP и отображения её на странице обзора в разделе Статус.

## Совместимость с темами

Компонент и страница используют стандартные структурные классы LuCI, такие как cbi-section, table, tr, td и ifacebadge, благодаря чему хорошо следуют текущей модели макета LuCI и корректно работают с luci-theme-argon без необходимости дополнительных CSS-переопределений для конкретной страницы.

## Источник данных

Бэкенд считывает информацию SFP через ethtool:

- ethtool -m &lt;ifname&gt;: чтение телеметрии DOM и информации о модуле.
- ethtool &lt;ifname&gt;: чтение состояния канала и скорости.

Если интерфейс не настроен, бэкенд автоматически определяет все сетевые устройства, с которых можно прочитать данные SFP DOM, и отображает их поочерёдно на странице обзора.

Пакет указывает ethtool как жёсткую зависимость, чтобы после установки сразу были доступны реальные данные DOM. Перед установкой локального ipk убедитесь, что в источниках пакетов вашего устройства доступен пакет ethtool, соответствующей архитектуры.

## Описание файлов

- root/usr/libexec/rpcd/luci.sfp-status: бэкенд rpcd, предоставляющий ubus-метод luci.sfp-status.
- htdocs/luci-static/resources/view/status/include/15_sfp.js: компонент страницы обзора.
- root/usr/share/rpcd/acl.d/luci-app-sfp-status.json: определение прав только для чтения ACL LuCI.

## Сборка

Поместите каталог этого пакета в LuCI feed или в каталог feeds/luci/applications/, затем выполните стандартную сборку OpenWrt:

```sh
make menuconfig
make package/feeds/luci/luci-app-sfp-status/compile V=s
```

## Сборка через GitHub Actions

Репозиторий уже содержит рабочий процесс GitHub Actions [main.yml](../.github/workflows/main.yml), который позволяет автоматически собирать этот плагин.

Рабочий процесс выполняет следующее:

- По умолчанию скачивает официальный SDK OpenWrt 24.10.0 для устройств ARMv8 (mediatek/filogic).
- Монтирует luci-app-sfp-status из текущего репозитория в каталог SDK feeds/luci/applications/ и явно регистрирует его в package/feeds/luci.
- Устанавливает определения пакетов luci-base.
- Запускает make package/feeds/luci/luci-app-sfp-status/compile для генерации ipk.
- Загружает сгенерированный ipk как артефакт GitHub Actions.
- После успешной сборки версии с тегом автоматически публикует ipk в GitHub Releases.

Способ использования:

1. Отправьте репозиторий на GitHub.
2. Откройте страницу Actions репозитория.
3. Выберите рабочий процесс Build luci-app-sfp-status.
4. Нажмите Run workflow для ручного запуска; по умолчанию используется целевая платформа mediatek/filogic для ARMv8; при необходимости можно изменить target/subtarget перед запуском.
5. Скачайте сгенерированный файл ipk из раздела Artifacts текущего запуска.

Автоматическая публикация Release:

- Создайте локальный тег версии, например:

```sh
git tag v0.1.0
git push origin v0.1.0
```

- GitHub Actions сначала соберёт плагин.
- После успешной сборки рабочий процесс автоматически создаст или обновит GitHub Release с таким же именем.
- Сгенерированный ipk автоматически загрузится как вложение к данному Release.

Ручная публикация Release:

1. Откройте страницу Actions и запустите Build luci-app-sfp-status.
2. Установите publish_release в true.
3. Укажите release_tag, например v0.1.0.
4. Рабочий процесс автоматически опубликует в соответствующий GitHub Release после успешной сборки.

Примечания:

- Пакет объявлен как all архитектуры в Makefile, поэтому даже если рабочий процесс по умолчанию использует SDK ARMv8 mediatek/filogic для сборки, результирующий пакет по-прежнему будет all.ipk.
- Теперь целевая платформа по умолчанию — сцена ARMv8; если ваше устройство относится к другой платформе ARMv8, можно изменить target/subtarget на нужное значение при ручном запуске рабочего процесса.
- Если в дальнейшем нужно строго следовать конкретной минорной версии OpenWrt 24.10, можно изменить openwrt_version при ручном запуске или скорректировать значение по умолчанию в рабочем процессе.
- Процесс публикации Release запускается только по тегу версии или при ручной установке publish_release; обычные коммиты по-прежнему только собираются и загружаются как артефакты, не засоряя страницу Releases.

## Проверка работы

После установки сгенерированного apk выполните:

```sh
apk add --allow-untrusted luci-app-sfp-status_0.1.0-r29_all.apk
ubus -v list luci.sfp-status
ubus call luci.sfp-status getStatuses '{}'
```

> **Внимание**: OpenWrt 25.12+ / ImmortalWrt 25.12+ используют формат APK. Собранные вручную `.apk` не подписаны, поэтому при установке необходимо добавить `--allow-untrusted`.
> Чтобы разрешить установку неподписанных пакетов навсегда, выполните на маршрутизаторе:
>
> ```sh
> echo 'allow_untrusted = yes' > /etc/apk/keys/policy.conf
> ```

Затем откройте LuCI:

- После обновления отдельный пункт страницы SFP в меню Статус больше не отображается.
- Если ранее открывалась старая версия страницы, выполните принудительное обновление, чтобы не использовать кешированный старый JS-файл.
- Перейдите в Статус > Обзор и убедитесь, что каждый обнаруженный модуль SFP отображается отдельно и корректно отображается при использовании темы luci-theme-argon.
